Django URLs:
--> Views are Python functions or classes that handle HTTP requests and return HTTP responses. To make views accessible through specific URLs, Django uses a URL configuration system known as URLConf. This system maps URL patterns to corresponding views, enabling precise request routing.





***Understanding URLConf***:
--> URLConf directs incoming requests to the appropriate view based on defined URL patterns.
a.) ROOT_URLCONF in settings.py specifies the root URL configuration module (usually project_name.urls).
b.) Each URLConf module defines a variable urlpatterns, which is a list of URL patterns.
c.) URL patterns are evaluated in order, the first match invokes its corresponding view.
d.) If no pattern matches, Django triggers the default error handler (e.g., 404).





***Structure of URLConf***:
--> URLConf modules organize URL patterns for both project-level and app-level routing.
a.) Use path() to map a URL pattern to a view.
b.) include() allows inclusion of app-specific URL configurations, keeping the project modular.
Example: project-level urls.py
CODE:
    from django.contrib import admin
    from django.urls import path, include

    urlpatterns = [
        path('admin/', admin.site.urls),
        path('', include('books.urls')),
    ]
--> In the above example:
a.) path('admin/', admin.site.urls) maps /admin/ to the Django admin interface.
b.) path('', include('books.urls')) delegates URL matching to the books app. 

Example: App-level urls.py:
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('', views.book_index, name='book_index'),
        path('<int:pk>/', views.book_detail, name='book_detail'),
    ]





***URL Patterns***:
--> URL patterns define the routes Django uses to match incoming HTTP requests to views.
a.) URL patterns are stored in the urlpatterns list in a URLConf module.
b.) Each entry in urlpatterns typically uses the path() function to associate a URL pattern with a view.
c.) Dynamic parts of a URL can be captured using path converters and passed as arguments to views.
d.) Using the name argument in a path allows reverse URL resolution, useful in templates and views.
Example: urls.py for a books app
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('books/', views.book_index, name='book_index'),
        path('books/<int:pk>/', views.book_detail, name='book_detail'),
        path('books/genre/<str:genre>/', views.books_by_genre, name='books_by_genre'),
    ]
--> In the above example:
i.) path('books/<int:pk>/') retrieves a book by ID.
ii.) path('books/<str:genre>/') filters books by genre.
iii.) path('books/') matches the book listing page.
iv.) Using name='...' allows references in templates using {% url 'name' %} and in Python code using reverse().






***Example: Basic Django URL Routing with HTML Pages***:
1. Define views in views.py:
CODE:
    from django.http import HttpResponse
    from django.shortcuts import render

    def home_view(request):
        return render(request, 'home.html')

    def about_view(request):
        return render(request, 'about.html')

    def contact_view(request):
        return render(request, 'contact.html')





***Path Converters***:
--> Path converters capture dynamic values from URLs and pass them as arguments to views. They are specified inside angle brackets < > in URL patterns.
i.) int: matches positive integers and converts the captured value to a Python int.
ii.) str: matches any non-empty string excluding the path separator /.
iii.) slug: matches letters, numbers, hyphens, and underscores, suitable for readable URLs.
iv.) path: matches any non-empty string, including the path separator /.
v.) uuid: matches a valid UUID string and converts it to a Python UUID object.
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('books/<int:pk>/', views.book_detail, name='book_detail'),
        path('books/<str:genre>/', views.books_by_genre, name='books_by_genre'),
        path('books/<slug:slug>/', views.book_by_slug, name='book_by_slug'),
    ]
--> In the above example:
a.) <int:pk> passes an integer primary key to the view.
b.) <str:genre> passes a string representing the book genre.
c.) <slug:slug> passes a slug string for human-readable URLs.
