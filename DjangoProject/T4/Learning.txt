Django URLs:
--> Views are Python functions or classes that handle HTTP requests and return HTTP responses. To make views accessible through specific URLs, Django uses a URL configuration system known as URLConf. This system maps URL patterns to corresponding views, enabling precise request routing.





***Understanding URLConf***:
--> URLConf directs incoming requests to the appropriate view based on defined URL patterns.
a.) ROOT_URLCONF in settings.py specifies the root URL configuration module (usually project_name.urls).
b.) Each URLConf module defines a variable urlpatterns, which is a list of URL patterns.
c.) URL patterns are evaluated in order, the first match invokes its corresponding view.
d.) If no pattern matches, Django triggers the default error handler (e.g., 404).





***Structure of URLConf***:
--> URLConf modules organize URL patterns for both project-level and app-level routing.
a.) Use path() to map a URL pattern to a view.
b.) include() allows inclusion of app-specific URL configurations, keeping the project modular.
Example: project-level urls.py
CODE:
    from django.contrib import admin
    from django.urls import path, include

    urlpatterns = [
        path('admin/', admin.site.urls),
        path('', include('books.urls')),
    ]
--> In the above example:
a.) path('admin/', admin.site.urls) maps /admin/ to the Django admin interface.
b.) path('', include('books.urls')) delegates URL matching to the books app. 

Example: App-level urls.py:
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('', views.book_index, name='book_index'),
        path('<int:pk>/', views.book_detail, name='book_detail'),
    ]





***URL Patterns***:
--> URL patterns define the routes Django uses to match incoming HTTP requests to views.
a.) URL patterns are stored in the urlpatterns list in a URLConf module.
b.) Each entry in urlpatterns typically uses the path() function to associate a URL pattern with a view.
c.) Dynamic parts of a URL can be captured using path converters and passed as arguments to views.
d.) Using the name argument in a path allows reverse URL resolution, useful in templates and views.
Example: urls.py for a books app
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('books/', views.book_index, name='book_index'),
        path('books/<int:pk>/', views.book_detail, name='book_detail'),
        path('books/genre/<str:genre>/', views.books_by_genre, name='books_by_genre'),
    ]
--> In the above example:
i.) path('books/<int:pk>/') retrieves a book by ID.
ii.) path('books/<str:genre>/') filters books by genre.
iii.) path('books/') matches the book listing page.
iv.) Using name='...' allows references in templates using {% url 'name' %} and in Python code using reverse().






***Example: Basic Django URL Routing with HTML Pages***:
1. Define views in views.py:
CODE:
    from django.http import HttpResponse
    from django.shortcuts import render

    def home_view(request):
        return render(request, 'home.html')

    def about_view(request):
        return render(request, 'about.html')

    def contact_view(request):
        return render(request, 'contact.html')





***Path Converters***:
--> Path converters capture dynamic values from URLs and pass them as arguments to views. They are specified inside angle brackets < > in URL patterns.
i.) int: matches positive integers and converts the captured value to a Python int.
ii.) str: matches any non-empty string excluding the path separator /.
iii.) slug: matches letters, numbers, hyphens, and underscores, suitable for readable URLs.
iv.) path: matches any non-empty string, including the path separator /.
v.) uuid: matches a valid UUID string and converts it to a Python UUID object.
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('books/<int:pk>/', views.book_detail, name='book_detail'),
        path('books/<str:genre>/', views.books_by_genre, name='books_by_genre'),
        path('books/<slug:slug>/', views.book_by_slug, name='book_by_slug'),
    ]
--> In the above example:
a.) <int:pk> passes an integer primary key to the view.
b.) <str:genre> passes a string representing the book genre.
c.) <slug:slug> passes a slug string for human-readable URLs.








***Django URL Dispatcher & Advanced URL Techniques***
--> Django URL Dispatcher maps incoming HTTP requests to views, enabling precise request routing. It supports dynamic URLs, named patterns, namespaces and class-based views for scalable, maintainable web applications.



**Creating URL Patterns**:
--> URL patterns define how URLs are routed to views. They are stored in the urlpatterns list in a Django app's urls.py.
--> Steps to create URL patterns:
a.) Open urls.py in the app or project.
b.) Import path() from django.urls.
c.) Define URL patterns and map them to views.
Example: urls.py
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('home/', views.home_view, name='home'),
        path('about/', views.about_view, name='about'),
    ]
--> In the above example:
a.) 'home/' mapped to home_view.
b.) 'about/' mapped to about_view.
c.) name='home' and name='about' allow easy reference in templates and Python code.




***Using Regular Expression***
--> For most URL patterns, Django’s path() with converters is preferred. For more complex matching requirements, Django provides re_path() with regular expressions to capture dynamic values from URLs.
--> Steps to use regex captures:
a.) Use path() for standard dynamic URLs and re_path() only when complex pattern matching is needed.
b.) Define a re_path() pattern using regex capturing groups ().
c.) Add parameters in the view for each captured value.
Example: urls.py
CODE:
    from django.urls import re_path
    from . import views

    urlpatterns = [
        re_path(r'^blog/(?P<blog_id>\d+)/\$', views.blog_detail, name='blog_detail'),
    ]
--> In the above example:
a.) (?P<blog_id>\d+) captures an integer from the URL.
b.) The view is called as blog_detail(request, blog_id=1) for /blog/1/.



***Naming URL Patterns***:
--> Named URL patterns allow referencing URLs without hardcoding paths in templates or Python code.
--> Steps to name URL patterns:
a.) Add the name argument to the path() function.
d.) Use {% url 'name' %} in templates.
c.) Use reverse('name') in Python code
Example: urls.py
CODE:
    from django.urls import path
    from . import views

    urlpatterns = [
        path('home/', views.home_view, name='home'),
        path('about/', views.about_view, name='about'),
    ]
--> In the above example:
a.) name='home' and name='about' assign a name to the URL patterns.
b.) Templates can use {% url 'home' %} and {% url 'about' %}.
c.) Python code can use reverse('home') and reverse('about').





***Inverting URL Patterns***
--> Inverting URLs generates URLs from their names instead of hardcoding paths.
--> Steps to invert URL patterns:
a.) Use {% url 'url_name' %} in templates.
b.) Use reverse('url_name') in Python code.
Example: template
CODE:
    <a href="{% url 'home' %}">Home</a>
Example: Python view
    from django.urls import reverse
    home_url = reverse('home')
--> In the above example:
a.) {% url 'home' %} generates the URL mapped to the 'home' route in the URL configuration.
b.) reverse('home') returns the URL associated with the 'home' route in Python code.







***Using Namespaces***
--> Namespaces organize URL patterns, avoiding naming conflicts when multiple apps exist.
--> Steps to use namespaces:
a.) Include app URLs in the project urls.py with namespace parameter.
b.) Reference URLs using 'namespace:url_name' in templates or Python code.
Example: urls.py
CODE:
    from django.urls import path, include

    urlpatterns = [
        path('books/', include(('books.urls', 'books'), namespace='books')),
    ]
Example: template reference
<a href="{% url 'books:book_detail' book_id=1 %}">Book Detail</a>
--> In the above example:
a.) namespace='books' groups URLs under the books namespace.
b.) {% url 'books:book_detail' book_id=1 %} references namespaced URL in template.
c.) reverse('books:book_detail', kwargs={'book_id': 1}) references namespaced URL in Python code.








***Using Class-Based Views (CBVs)***
--> Class-based views provide reusable and organized view logic.
--> Steps to use CBVs:
a.) Create a Python class inheriting from View or generic CBVs.
b.) Define methods like get() or post().
c.) Map the class to a URL using .as_view()
Example: views.py
CODE:
    from django.views import View
    from django.http import HttpResponse

    class ItemListView(View):
        def get(self, request):
            return HttpResponse("List of items")
Example: urls.py
CODE:
    from django.urls import path
    from .views import ItemListView

    urlpatterns = [
        path('items/', ItemListView.as_view(), name='item-list'),
    ]

--> In the above example:
a.) ItemListView defines a get method for GET requests.
b.) .as_view() converts the class into a callable view.
c.) 'items/' URL maps to the CBV, and name='item-list' allows referencing it.
